# Game Studio Plan 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `profiles/` installer into a `studios/` installer that loads the `game-dev` studio as a live Claude Code plugin, and ship the four stage skills (`studio`, `brainstorm`, `plan`, `execute`) plus the state tool and session hook they need, so a feature in an existing Godot project can be planned and executed through `claude-gd`.

**Architecture:** A studio directory is simultaneously a Claude Code plugin (`.claude-plugin/plugin.json`, `skills/`, `agents/`, `hooks/`) and an installer manifest (`studio.json`, `requires.txt`, `CLAUDE.md`, `settings.json`, `memory/`, `bin/`). `install.sh` places only what Claude Code must own into the isolated config root and writes a shim that launches `claude` with `CLAUDE_CONFIG_DIR`, a `PATH` prefix for `bin/`, and `--plugin-dir` pointing at the studio, so skills are live from the repository. Stage skills read and write `.studio/STATE.md` in the game project through one tool, `studio-state`, and delegate generic mechanics to superpowers skills by exact name.

**Tech Stack:** POSIX `sh` (no bash-isms, no new dependencies), the existing `lib/common.sh` helpers and `tests/assert.sh` harness, Claude Code plugin conventions (plugin manifest, `SKILL.md` frontmatter, agent frontmatter, `hooks.json` with `${CLAUDE_PLUGIN_ROOT}`), Markdown skills.

**Spec:** `docs/game-dev/specs/2026-09-13-game-studio-design.md` — this plan implements its "Delivery — Plan 1 — Foundation" scope: the sections "Concept model", "Install behavior" (steps 1–7 and 9; step 8, MCP registration, is Plan 2), "Renames", "Repository layout", "Session bootstrap hook", "Workflow" (the `studio`, `brainstorm`, `plan`, `execute` skills), "State and configuration", and "Testing the framework" cases 1–6, 8 (bin syntax) and 11. The doctor delegation check (case 7), the role agents, and the engine toolkit are Plans 2 and 3.

## Global Constraints

Copied from the spec; every task's requirements include these.

- POSIX `sh` only, for every script and test. No bash-isms, no new dependencies (`jq` may be used *when present*, never required).
- The `guard_target` safety property is unchanged: an install or uninstall refuses `~/.claude`, the home directory, and any path inside the repository, after canonicalizing the path. Install paths must not contain spaces.
- Every user-facing string says "studio", never "profile". `profiles/` → `studios/`, `profile.json` → `studio.json`, `resolve_profile_target` → `resolve_studio_target`.
- `studio.json` is flat JSON readable by `json_field`. game-dev's keys: `name`, `description`, `target` (`~/.claude-gamedev`), `shim` (`claude-gd`), `engine` (`godot4`), `dimension` (`2d`), `language` (`gdscript`), `tests` (`gut`).
- `.claude-plugin/plugin.json` has `name` equal to the studio directory name, `version` `0.1.0`, and a `description`. The plugin name is what produces the `game-dev:` prefix.
- `requires.txt` lines are `<kind> <name>` with kind `plugin`, `skill`, or `agent`. Every `superpowers:` or `godot-prompter:` name referenced in `skills/`, `agents/` or `engines/` must appear in it.
- The config root receives exactly: rendered `CLAUDE.md`, copied `settings.json`, linked `memory/` and `bin/` entries, the manifest, and (copy mode) `studio/`. No `agents/`, `skills/`, `commands/` or `hooks/` directory is created in the target.
- The shim text is exactly:

  ```sh
  #!/usr/bin/env sh
  # Generated by omega-ai install.sh — launches Claude Code against the
  # <studio> studio's isolated config root with the studio plugin loaded live.
  OMEGA_STUDIO_ROOT="<plugin dir>"
  export OMEGA_STUDIO_ROOT
  CLAUDE_CONFIG_DIR="<target>" \
  PATH="<target>/bin:$PATH" \
    exec claude --plugin-dir "$OMEGA_STUDIO_ROOT" "$@"
  ```

  where `<plugin dir>` is `studios/<studio>` in the repository in symlink mode and `<target>/studio` in copy mode.
- `settings.json` is copied, never linked; a differing existing file is backed up to `settings.json.bak-<timestamp>`.
- Skill frontmatter: `name` equals the skill directory; `description` starts with "Use when". Agent frontmatter: `name` equals the file stem; `description` starts with "Use when"; a `tools` line; `model: inherit`.
- Skills reference superpowers skills only by these exact names: `superpowers:test-driven-development`, `superpowers:systematic-debugging`, `superpowers:using-git-worktrees`, `superpowers:verification-before-completion`, `superpowers:finishing-a-development-branch`, `superpowers:writing-plans`, `superpowers:executing-plans`, `superpowers:subagent-driven-development`. No invented names.
- `.studio/STATE.md` has the header fields `stage`, `spec`, `plan`, `task`, `last_playtest`, `milestone`, then a `## Ledger` section. `stage` ∈ {`idle`, `brainstorm`, `plan`, `execute`, `review`, `playtest`, `ship`, `retro`}; `milestone` ∈ {`prototype`, `vertical-slice`, `alpha`, `beta`, `gold`}; empty values are written as `-`; the ledger is append-only. All writes go through `studio-state`.
- `studio-state` exit codes: 0 ok; 1 no `.studio/` (except `init`), bad key, bad value, bad usage.
- Plan task format produced by `/game-dev:plan`: the superpowers writing-plans format plus `Role:` and `Verify: unit | playtest | visual` lines per task; TDD is mandatory only for `Verify: unit`.
- Execution default is subagent-driven; `--inline` selects checkpointed inline execution.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Never push.

```sh
# resolve_studio_target STUDIO_DIR [OVERRIDE] — print the studio's config
# root. OVERRIDE wins when given; otherwise studio.json's target is used.
# Dies when the studio, its studio.json, or the resolved target is missing.
resolve_studio_target() {
  _sdir="${1%/}"
  _override="${2:-}"
  _sname="$(basename "$_sdir")"
  [ -d "$_sdir" ] || die "unknown studio: $_sname"
  [ -f "$_sdir/studio.json" ] || die "studio has no studio.json: $_sname"
  if [ -n "$_override" ]; then
    _resolved="$(expand_path "$_override")"
  else
    _resolved="$(expand_path "$(json_field "$_sdir/studio.json" target)")"
  fi
  [ -n "$_resolved" ] || die "studio.json declares no target: $_sname"
  printf '%s\n' "$_resolved"
}

# requires_of FILE KIND — print the names a requires.txt declares for KIND
# (plugin, skill, or agent), one per line. A missing file prints nothing, so
# a studio with no dependencies needs only an empty requires.txt.
requires_of() {
  [ -f "$1" ] || return 0
  awk -v kind="$2" '$1 == kind { print $2 }' "$1"
}
```

```sh
#!/bin/sh
# studio-state — read and write .studio/STATE.md the same way from every
# skill. Run from the root of a game project.
#
#   studio-state init            create .studio/STATE.md (stage idle)
#   studio-state show            print the file
#   studio-state get KEY         print one field
#   studio-state set KEY VALUE   replace one field; '-' clears it
#   studio-state ledger TEXT     append a dated line to the ledger
#
# Keys: stage spec plan task last_playtest milestone
# Exit: 0 ok · 1 no .studio/ (except init), bad key, bad value, bad usage
set -eu

STATE=".studio/STATE.md"
KEYS="stage spec plan task last_playtest milestone"
STAGES="idle brainstorm plan execute review playtest ship retro"
MILESTONES="prototype vertical-slice alpha beta gold"

usage() {
  printf 'usage: studio-state init | show | get KEY | set KEY VALUE | ledger TEXT\nkeys: %s\n' "$KEYS" >&2
  exit 1
}

fail() { printf 'studio-state: %s\n' "$*" >&2; exit 1; }

# in_list WORD LIST — succeed when WORD is one of the space-separated LIST.
in_list() {
  for _w in $2; do [ "$_w" = "$1" ] && return 0; done
  return 1
}

need_state() {
  [ -f "$STATE" ] || fail "no $STATE here — run 'studio-state init' in the project root"
}

cmd="${1:-}"
[ -n "$cmd" ] || usage

case "$cmd" in
  init)
    [ ! -f "$STATE" ] || fail "$STATE already exists"
    mkdir -p .studio
    cat > "$STATE" <<'EOF'
# Studio State

stage: idle
spec: -
plan: -
task: -
last_playtest: -
milestone: prototype

## Ledger

EOF
    printf 'initialised %s\n' "$STATE"
    ;;
  show)
    need_state
    cat "$STATE"
    ;;
  get)
    need_state
    key="${2:-}"
    in_list "$key" "$KEYS" || usage
    sed -n "s/^$key: //p" "$STATE" | head -n 1
    ;;
  set)
    need_state
    key="${2:-}"
    val="${3:-}"
    in_list "$key" "$KEYS" || usage
    [ -n "$val" ] || usage
    case "$key" in
      stage) in_list "$val" "$STAGES" || fail "stage must be one of: $STAGES" ;;
      milestone) in_list "$val" "$MILESTONES" || fail "milestone must be one of: $MILESTONES" ;;
    esac
    tmp="$STATE.tmp.$$"
    # Only the first matching header line is replaced; ledger lines start
    # with "- " and can never match "^key: ".
    awk -v k="$key" -v v="$val" '
      BEGIN { done = 0 }
      !done && $0 ~ ("^" k ": ") { print k ": " v; done = 1; next }
      { print }
    ' "$STATE" > "$tmp"
    mv "$tmp" "$STATE"
    ;;
  ledger)
    need_state
    text="${2:-}"
    [ -n "$text" ] || usage
    printf -- '- %s %s\n' "$(date +%Y-%m-%d)" "$text" >> "$STATE"
    ;;
  *)
    usage
    ;;
esac
```

- [ ] **Step 3: Add `manifest_remove` to `lib/common.sh`**

Append after `manifest_add`:

```sh
# manifest_remove MANIFEST TARGET SHIM_PATH — delete every path the manifest
# records that lies under TARGET, plus the shim at SHIM_PATH, then delete the
# manifest itself. A missing manifest is a no-op.
#
# The manifest lives inside a user-writable root and can be stale from an
# install that used a different --target or --shim-dir, so entries outside
# TARGET are skipped with a warning. Scope is decided on the canonical form of
# both sides: a '..' spelling such as "$TARGET/../.claude/settings.json"
# matches "$TARGET/*" textually while pointing outside the root entirely. The
# removal itself uses the entry exactly as written, so a path the kernel
# cannot resolve deletes nothing rather than deleting the folded path instead.
manifest_remove() {
  _m="$1"; _scope_root="$2"; _shim="$3"
  [ -f "$_m" ] || return 0
  _scope_canon="$(canon_path "$_scope_root")"
  while IFS= read -r _entry; do
    [ -n "$_entry" ] || continue
    _entry_canon="$(canon_path "$_entry")"
    _in_scope=0
    case "$_entry_canon" in
      "${_scope_canon%/}"/*) _in_scope=1 ;;
    esac
    if [ -n "$_shim" ] && [ "$_entry_canon" = "$_shim" ]; then _in_scope=1; fi
    if [ "$_in_scope" != "1" ]; then
      warn "skipping manifest entry outside $_scope_root: $_entry"
      continue
    fi
    rm -rf "$_entry"
  done < "$_m"
  rm -f "$_m"
}
```

```sh
#!/bin/sh
# SessionStart hook for the game-dev studio. Prints hooks/bootstrap.md as the
# session's additional context, with the identity line filled from the
# project's .studio/config.json (falling back to the studio's own defaults).
#
# Self-contained on purpose: in copy mode the plugin root is a snapshot with
# no lib/common.sh beside it.
set -u

ROOT="${CLAUDE_PLUGIN_ROOT:-$(cd "$(dirname "$0")/.." && pwd)}"

# field FILE KEY — value of a flat JSON string key; empty when absent.
field() {
  [ -f "$1" ] || return 0
  sed -n 's/.*"'"$2"'"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$1" | head -n 1
}

# pick KEY — the project's value when it has one, else the studio default.
pick() {
  _v="$(field ".studio/config.json" "$1")"
  [ -n "$_v" ] || _v="$(field "$ROOT/studio.json" "$1")"
  printf '%s' "$_v"
}

# label VALUE — the display form of a configuration value.
label() {
  case "$1" in
    godot4) printf 'Godot 4.x' ;;
    2d) printf '2D' ;;
    3d) printf '3D' ;;
    gdscript) printf 'GDScript' ;;
    csharp) printf 'C#' ;;
    gut) printf 'GUT' ;;
    gdunit4) printf 'gdUnit4' ;;
    '') printf 'unset' ;;
    *) printf '%s' "$1" ;;
  esac
}

ENGINE="$(label "$(pick engine)")"
DIMENSION="$(label "$(pick dimension)")"
LANGUAGE="$(label "$(pick language)")"
TESTS="$(label "$(pick tests)")"

TAB="$(printf '\t')"
# Fill the identity line, then escape for a JSON string: backslash, quote,
# tab, and newlines (joined into one line by awk). Carriage returns are dropped.
escaped="$(sed -e "s/{{ENGINE}}/$ENGINE/g" \
               -e "s/{{DIMENSION}}/$DIMENSION/g" \
               -e "s/{{LANGUAGE}}/$LANGUAGE/g" \
               -e "s/{{TESTS}}/$TESTS/g" "$ROOT/hooks/bootstrap.md" \
  | tr -d '\r' \
  | sed -e 's/\\/\\\\/g' -e 's/"/\\"/g' -e "s/$TAB/\\\\t/g" \
  | awk 'BEGIN { ORS = "" } NR > 1 { printf "\\n" } { printf "%s", $0 }')"

printf '{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"%s"}}\n' "$escaped"
```

````markdown
# omega-ai

Version-controlled Claude Code **studios** — each a plugin (skills, agents,
hooks) plus a small manifest — installable into its own isolated config
directory. Installing a studio never touches `~/.claude`. Switching between
assistants is a matter of which command you type.

## Studios

| Studio | Config root | Launch | Purpose |
|---|---|---|---|
| `game-dev` | `~/.claude-gamedev` | `claude-gd` | A small game studio: stage skills, role agents, Godot 4.x 2D toolkit |
| `general` | `~/.claude-general` | `claude-gen` | Minimal clean-room studio |

## Install

```sh
./install.sh game-dev
```

This creates `~/.claude-gamedev` with a rendered `CLAUDE.md`, a copied
`settings.json`, and links to the studio's `memory/` and `bin/`; writes a shim
at `~/.local/bin/claude-gd`; and runs `doctor.sh`. The shim launches Claude
Code with `CLAUDE_CONFIG_DIR` pointing at the config root, the studio's
`bin/` on `PATH`, and `--plugin-dir` pointing at `studios/game-dev/`, so the
studio's skills, agents and hooks load straight from this checkout — edit a
skill and it is live in the next session.

Add `~/.local/bin` to your `PATH` if it is not there already. Then:

```sh
claude       # your existing setup, unchanged
claude-gd    # the game-dev studio
```

The first `claude-gd` launch fetches the plugins the studio depends on
(superpowers, godot-prompter) into the isolated config root.

Options: `--mode copy` for a frozen snapshot (the studio is copied to
`~/.claude-gamedev/studio/` and loaded from there), `--target DIR` for a
different config root, `--shim-dir DIR` for a different shim location,
`--no-mcp` to skip MCP registration, and `--dry-run` to see every action
without performing it. Reinstalling removes everything the previous install
recorded first.

Install paths must not contain spaces.

| `/game-dev:execute` | Fresh subagent per task, reviewer after each; `--inline` for checkpointed execution |

`review`, `playtest`, `ship`, `retro` and `scaffold` arrive in later releases;

## What is and is not isolated

Isolated per studio: `CLAUDE.md`, `settings.json`, plugins, sessions,
history, and memory. The studio's own skills, agents and hooks come from the
plugin directory and are never copied into the config root in symlink mode.

Not isolated, by design: a project's own `CLAUDE.md` and `.claude/` directory
load in every studio, because they describe the project rather than the
assistant. System- or enterprise-managed settings also still apply.
````
